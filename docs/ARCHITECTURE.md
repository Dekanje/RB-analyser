# Target architecture (proposed; audit before redesign)
Versioned card catalog + format manager -> legal registration validator -> pinned C++ AlphaRune + overlay -> observation/action interface -> heuristic/ISMCTS/learned agents -> native BO3 executor -> Python optimization workers -> tournament engine -> independent validation -> reports/UI. Store immutable manifests and content-addressed deck/engine/rules/agent hashes; use SQLite/DuckDB and Parquet only where justified. Local Linux/WSL2 worker pool with deterministic job partition, atomic checkpoints and resume; CI smoke/targeted/full gates, not bulk training. Separate native execution from statistical tournament model; both consume versioned rules. Preserve existing scripts, overlay and workflows pending audit. No paid API or required LLM during execution.
