# RB-Analyser 2.0 — approved master plan
Baseline: 2026-11-24. Objective: research-grade autonomous Riftbound deck discovery and tournament optimization, without Astra or mandatory paid services. All legal legends, all legal functional cards and configurable rules. Existing 58 legends imply 58×57=3,306 directed non-mirror matchup objectives, 58 meta and 58 universal objectives (3,422 total); mirror support adds 58 optional matchup objectives. Championship optimization selects or refines candidates independently; no global optimum or real-world victory guarantee.
## Phase gates
Each gate requires source evidence, reproducible tests, documented limitations and review. Existing work may satisfy portions only after verification. Statistical validation begins at phase 0; tournament skeleton begins immediately after BO3, before tournament-oriented optimization.
| Phase | Implementation steps | Acceptance gate |
|---|---|---|
| 0 Baseline | Inventory branches, pinned upstream, overlay, build/test workflows, card coverage, agent strength, optimizer, artifacts, licensing; reproduce latest baseline; profile; classify verified/partial/missing/defective/unknown | Evidence matrix, reproducible build and exact backlog; no unverified promotion |
| 1 Data and formats | Functional IDs, print equivalence, card text/errata provenance, domain and legend legality, bans, set rotation, chosen champion, runes, battlefields, sideboard, future sets | Complete selected legal pool enumerated; unknown/unsupported quarantined explicitly |
| 2 Rules | Initialization, turns, priority, costs, movement, combat, scoring, triggers, replacements, continuous effects, targets, simultaneous effects, tokens, legend abilities, cross-set interactions, deterministic replay | Every legal identity mapped to behavioral tests; no known critical defect; invariants, fuzz and ruling-derived fixtures pass |
| 3 Performance | Benchmark CPU/RAM/state copy/action generation, hash/cache, parallel workers, checkpoint/resume, replay equivalence | Measured throughput and deterministic correctness; no degraded search or lost work |
| 4 Gameplay | Random/heuristic baselines, tactical evaluation, resources, sequencing, threat/scoring, hidden-state sampling, ISMCTS budget, opponent modeling | Paired and held-out agent comparisons, leakage tests, expert scenarios; strength empirically supported |
| 5 Self-play | Log observations/actions/outcomes, train policy/value models, frozen historical opponents, promotion/rollback, diversity and holdout separation | Statistically supported strength across archetypes, no material unexamined regressions |
| 6 Synergy | Structured effects, resource/card advantage, combo and anti-synergy, legend interaction graphs, simulation-based validation | Independent discovery and validation of multi-card packages |
| 7 Independent archetypes | Legal generation from scratch, diverse initial populations, aggro/control/tempo/combo/hybrid, rune/battlefield/champion optimization, clustering | All legends covered, diverse candidates where feasible; blind data isolation |
| 8 Evolution | Single/multi-card swaps, 3–5 card and larger packages, quantities, crossover, annealing/restarts, adaptive sampling, elite diversity | Reproducible improvements on fresh seeds and opponents; no screening-only adoption |
| 9 BO3 and tournament skeleton | Correct match progression, mulligans, first player, registered pool, sideboard plans, observed information, match draws/clock, basic Swiss and cuts | Native receipts, legal transitions, complete matches; core tournament fixtures pass before use |
| 10 Matchup optimization | Directed legend pair objectives, strong multiple archetypes, sideboard strategy, holdouts, improved opponents, mirrors | All 3,306 non-mirror objectives addressed at 58 legends; uncertainty and unsupported cases explicit |
| 11 Meta | Verified event decks, representation/recency, plausible future fields, meta-weighted search and sideboards | All legends optimized against multiple documented field assumptions |
| 12 Universal | Average, lower-tail and worst-case matchup objectives, Pareto frontier, consistency, universal sideboards | All legends independently optimized; trade-offs and unseen archetype stress tests |
| 13 Co-evolution | Diverse populations per legend, frozen generations, challenger pools, exploitability, stagnation, independent budgets, alternate agent/deck learning | Improvements against historical and challenger pools without intentional weakening |
| 14 Statistical QA | Independent seeds/opponents, paired comparisons, uncertainty, multiplicity, calibration, independent agents and expert fixtures | Reproducible results; distinguish inconclusive from improvements; no leakage |
| 15 Championship | Official versioned Swiss, multi-day cut, tiebreakers, seeding, elimination, full/probability modes, skill and field uncertainty | Full tournament fixtures and cross-validation; per-legend qualification/top-cut/title probabilities and intervals |
| 16 UI | Local controls, progress, match matrix, decks, replay, QA, CSV/Parquet export, resource monitor | Start/pause/resume and reproduce without editing code |
| 17 Maintenance | Detect new sets/errata/bans/rules, quarantine changes, invalidate caches, regressions and reoptimization | Versioned repeatable maintenance; changed mechanics require verification |
## Priorities
Phase 0 now; no new mass optimization until baseline evidence is reconciled. Phase 2 and 4 accuracy precede production rankings. Implement basic tournament framework after Phase 9; Phase 15 extends and validates it. Use local compute, CI smoke/targeted tests on commits, full validation at milestones. Never declare a phase done solely from green CI. See docs/TOURNAMENT_SPEC.md, docs/QA_REQUIREMENTS.md and docs/OPTIMIZATION_SPEC.md.
