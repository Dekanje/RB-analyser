# RB-Analyser 2.0 — permanent agent instructions
Read MASTER_PLAN.md, DEVELOPMENT_STATUS.md, KNOWN_LIMITATIONS.md and docs/HANDOVER.md before development. Verify the actual branch/ref, latest commits, CI runs and artifacts; main is not necessarily the latest engine. Follow the next unfinished acceptance gate. Do not treat chat memory as authoritative.
Mission: independently discover the strongest achievable legal deck for every legend and maximize championship win probability. Never weaken opponents or omit unsupported cards/legends silently. Keep blind discovery separate from public-meta optimization. Support configurable official/hypothetical formats, including Worlds without Legacy. All claims must distinguish executed simulations, projections, heuristics and unknowns.
Preserve verified components; justify rewrites. Prefer existing C++/Python, free tools, local PC and GitHub CI. No mandatory paid AI/API/infrastructure. Pin source, overlay, registry, ruleset, agents, decks and random seeds. Fail closed on invalid games, illegal actions or unsupported mechanics. Prevent hidden-information and train/validation leakage. Include tests for every change; investigate failures; passing tests are not exhaustive proof.
Use isolated branches for code changes and targeted tests before full gates; never overwrite validated decks with screening results. Record test/run IDs, commit, hashes, sample sizes, intervals, known limitations and next action in status/handover after every milestone. Update decision and change logs. No fabricated progress, asynchronous work or unverified completion claims. Never commit secrets or unauthorized copyrighted card-text dumps. Do not change repository visibility without permission.
